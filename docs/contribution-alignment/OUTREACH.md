# Permission-first outreach — nothing sent

This document prepares wording only. Neither issue #18 nor this PR authorizes
contact. Keep technical collaboration separate from governance research: do not
attach a research pitch to an upstream bug/feature discussion or imply an upstream
contribution requires participation.

## Recruitment sequence

1. Dogfood here and obtain the owner's scoped decision; preserve field test #8.
2. Run offline replay before asking anyone to test a prototype. Concept feedback,
   if separately authorized, must say it is a document, not working software.
3. Select a small number of relevant people using public, documented preferred
   contact channels. Verify current roles and discussion status before proposing
   any recipient. Public authorship is not consent or proof of maintainer authority.
4. Obtain separate approval of the exact recipient, channel and message. Send one
   personal opt-in invitation; no bulk messages, tagging campaign, private-contact
   scraping or automatic follow-ups. Silence means no consent. Follow up only if invited.
5. Before a prototype session, satisfy [build gates](BUILD_PLAN.md) and explain
   [consent/privacy](EXPERIMENT.md). Targets of 2–3 maintainers and 3–6 contributors
   are recruitment goals only. Withdrawal needs no justification.

## Unsent concept-stage invitations

**Maintainer:** “We are exploring whether source-linked contributor preflight and
short decision briefs could reduce coordination work without adding another queue.
We have a written concept, not a contribution-alignment prototype. Would you be
open to reading a short example and telling us whether a static policy document
would do the job better? This is a governance-research invitation, not a request
to install anything or endorse the project. Declining needs no explanation.”

**Contributor:** “We have a written idea for a pre-coding check showing related
work, explicit project constraints and unresolved decisions. There is no working
contribution-alignment prototype yet. Would you be willing to comment on one
example? It would not score contributors, reserve tasks or guarantee acceptance.
Taking part would be separate from any contribution you make.”

## Unsent prototype-stage invitations — conditional wording

Use only after the scoped prototype exists, relevant gates pass, and the statements
below have been verified. Do not send these as concept-stage claims.

**Maintainer:** “We have a small read-only contribution-preflight prototype using
public or synthetic evidence. We would like to compare it with GitHub and your
existing docs, including setup, checking and correction time. Would you opt into a
moderated session? No repository installation or bot posting is required for this
demo. We will explain data handling before you decide; declining has no consequence.”

**Contributor:** “Would you opt into trying our read-only preflight prototype on one
proposed change and comparing it with ordinary GitHub/docs? We want to find where
it misses related work or incorrectly suggests overlap. It does not score you or
guarantee acceptance, and you can participate without an agent. We will agree what
is recorded before the session, and you can stop at any time.”

If the eventual setup requires an installation, new AI processing or other access,
rewrite the invitation and obtain authorization; do not reuse inaccurate wording.
